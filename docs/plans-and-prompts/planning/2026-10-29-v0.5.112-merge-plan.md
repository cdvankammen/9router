## 4. Guardrails (from master-coding-rule.md)

Every step MUST satisfy:

1. **Build-on-commit** — `npm run build` + vitest regression after each conflict resolution commit
2. **Triple-proof testing** — DOM + vitest + runtime smoke (per rule 6)
3. **Anti-false-positive** — intentionally break one assertion per new test to verify it catches failures
4. **Clean process state** — kill any stale 9router processes before runtime smoke
5. **No partial commits** — if a conflict resolution breaks the build, revert/fix before proceeding
6. **Document everything** — conflict resolutions logged to MERGE-21 conflict log (this doc, section 7)

**Additional merge-specific guardrails from MERGE-13:**
- Union dedup for import sets (never drop an import from either side)
- Semantic merge for handler signatures (chatCore.js family)
- Renumber provider registry entries when upstream adds new providers
- NEVER drop security fixes from ours (CORS Phase 3B, SSRF guards, requireAuth gates)
- ALWAYS regenerate `tests/__baseline__/*.json` post-merge via `scripts/migrate-registry.mjs` + `injectDisplayToRegistry.mjs` + vitest -u

### Option A: Single merge commit (RECOMMENDED)
```
git fetch origin
git checkout v5-vscode-works
# Snapshot T0 baseline
cp tests/__baseline__/providers-baseline.json /tmp/providers-pre-merge.json

git add -A && git commit  # merge commit
# Post-merge: regenerate baselines, run full suite, verify no regression
```

**Why single merge (not rebase):**
- Preserves 412-commit security hardening history intact
- Matches the v4→v5 merge pattern (664b0a42) that's already verified working
- Avoids rewriting 412 commits (force-push risk, signature invalidation)
- 14 commits is small enough that conflict resolution is tractable in one pass

### Option B: Cherry-pick upstream commits individually
- Use only if Option A produces unresolvable conflicts
- More work (14 picks) but isolates each change
- Loses upstream merge topology (author attribution preserved, but merge commit grouping lost)

### Option C: Rebase v5-vscode-works onto origin/master
- **DO NOT USE** — rewrites 412 commits, invalidates every SHA referenced in session memory, audit doc, and CHANGELOG
- Would require force-push and break every worktree

## 9. Learnings to Carry Forward (from prior merges)

1. **Always snapshot baselines pre-merge** — `/tmp/providers-pre-merge.json` + `/tmp/alias-pre-merge.json` so we can diff post-merge
2. **Never trust "no conflict" from git** — semantic conflicts (same file, different intent) don't produce markers. Inspect every file in section 3.2 manually.
3. **Regenerate registry after merge** — `scripts/migrate-registry.mjs` and `injectDisplayToRegistry.mjs` are NOT optional when `providers/registry/index.js` changes
4. **zsh commit escaping** — use multiple `-m` flags for multi-paragraph commit messages, never `\n` in double quotes (per user memory `zsh-commit-escaping.md`)
5. **Transparent follow-up > history rewriting** — if a conflict resolution breaks something, commit the fix transparently, don't amend the merge commit
6. **Source-ordering assertions are brittle** — tests that assert "line X comes before line Y" break on any reformat; scope to function body via indexOf (learned in session 20)
7. **Verify every source edit landed** — grep the file after replace_string_in_file; silent failures happen (learned in session 20)
