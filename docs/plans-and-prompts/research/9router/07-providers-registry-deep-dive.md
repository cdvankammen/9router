## Architecture Overview


registry/{id}.js  ──┐
                     ├──► registry/index.js (static import array)
REGISTRY_TEMPLATE.js ┘         │

                      providers/index.js

     PROVIDERS[id]    PROVIDER_MODELS[alias]    PROVIDER_OAUTH[id]  PROVIDER_MEDIA[id]
     (transport)      (normalized model[])      (oauth flow)        (media services)


**Data flow:**
1. Each `registry/{id}.js` exports a single default `RegistryEntry` object
2. `registry/index.js` (auto-generated by `scripts/migrate-registry.mjs` / `injectDisplayToRegistry.mjs`) static-imports all entries into an array
3. `providers/index.js` iterates the array once and populates four top-level maps:
   - `PROVIDERS[id]` — built from `entry.transport` via `buildTransport()`
   - `PROVIDER_MODELS[alias]` — `entry.models.map(normalizeModel)`
   - `PROVIDER_OAUTH[id]` — `entry.oauth`
   - `PROVIDER_MEDIA[id]` — aggregated from media-key fields + legacy `entry.media`

**Key invariant:** Transport and models are *co-located* in one file per provider. No separate "model catalog" file — every model lives in the same registry file as its provider.

## Infrastructure Files

### providers/index.js

**Single source of truth** for building the four runtime maps from the registry array.

#### Exports
| Export | Type | Description |
|--------|------|-------------|
| `PROVIDERS` | `Record<id, TransportConfig>` | Built from `entry.transport` for each entry with a transport |
| `PROVIDER_MODELS` | `Record<alias, NormalizedModel[]>` | Normalized model list (alias defaults to id) |
| `PROVIDER_OAUTH` | `Record<id, OAuthConfig>` | Entries with an `oauth` block |
| `PROVIDER_MEDIA` | `Record<id, MediaConfig>` | Aggregated media/service fields |

#### Core functions

```js
buildTransport(transport, oauth)

- Shallow-clones transport, fills `format: "openai"` default when absent
- Injects `clientId`, `clientSecret`, `tokenUrl` from `oauth` block into transport (so executors reading `config.{clientId,tokenUrl}` don't need to duplicate them in both places)

#### The loop

```js
for (const entry of REGISTRY) {
  if (entry.transport) {
    PROVIDERS[entry.id] = buildTransport(entry.transport, entry.oauth);
    if (entry.transports) PROVIDERS[entry.id].transports = entry.transports; // multi-endpoint
  }
  if (entry.models !== undefined) PROVIDER_MODELS[entry.alias || entry.id] = entry.models.map(normalizeModel);
  if (entry.oauth) PROVIDER_OAUTH[entry.id] = entry.oauth;
  // MEDIA_KEYS aggregation...
}
Object.assign(PROVIDER_MODELS, buildTtsProviderModels()); // TTS voice tables


**MEDIA_KEYS set:** `serviceKinds, ttsConfig, sttConfig, embeddingConfig, imageConfig, imageToTextConfig, videoConfig, musicConfig, searchViaChat, searchConfig, fetchConfig, modelsFetcher, mediaPriority, hiddenKinds`

### providers/schema.js

Defines the `RegistryEntry` typedef (JSDoc, not runtime-validated) and shared defaults.

#### Exports

| Export | Type | Purpose |
|--------|------|---------|
| `PROVIDER_DEFAULTS` | object | Shared transport defaults (documents contract) |
| `ENDPOINT_DEFAULTS` | object | Per-format default endpoints |
| `resolveProvider(entry)` | function | Deep-merges entry.transport over PROVIDER_DEFAULTS (currently unwired) |

#### `PROVIDER_DEFAULTS` (verbatim)

```js
{
  baseUrl: "",
  format: "openai",
  headers: {},
  auth: { header: "Authorization", scheme: "bearer", source: ["accessToken", "apiKey"] },

#### `ENDPOINT_DEFAULTS` (verbatim)

```js

  openai: { chat: "/chat/completions", test: "/models", models: "/models" },

#### `resolveProvider(entry)`

Deep-merges `{ ...PROVIDER_DEFAULTS, ...transport }` with merged nested objects (`headers`, `auth`, `quirks`, `retry`). Defensive against missing transport.

### providers/capabilities.js

Resolves what a model can read/do beyond plain text. **4-step fallback chain** (first match wins, merged over `DEFAULT_CAPABILITIES`):

1. `PROVIDER_CAPABILITIES[provider][model]` — provider-specific override
2. `MODEL_CAPABILITIES[model]` — exact id exception
3. `PATTERN_CAPABILITIES` — ordered glob (specific → generic)
4. `DEFAULT_CAPABILITIES` — safe floor

## Registry Patterns & Anatomy

### Universal structure of a registry file

```js
// Optional imports
import { CLAUDE_API_HEADERS, ... } from "../shared.js";
import { withCodexReviewModels } from "../models/helpers.js";

export default {
  // ── identity (REQUIRED) ─────────────
  id: "provider-id",          // kebab-case, unique
  alias: "short",             // PROVIDER_MODELS key (defaults to id)
  aliases: ["alt-name"],      // extra lookup tokens
  uiAlias: "UI",              // UI badge token

  // ── auth category (REQUIRED) ────────
  category: "apikey" | "oauth" | "freeTier" | "free",
  authType: "apikey" | "oauth" | "none",
  authModes: ["oauth", "apikey"],

  // ── HTTP transport ──────────────────

    baseUrl, baseUrls[], format, headers, auth,
