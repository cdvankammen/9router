## 2. The Goal System's Actual Injection Mechanism — This IS Replicable

Here's the exact protocol from `hook-runner.mjs`. A hook writes JSON to **stdout** with one of these shapes:


**The `systemMessage` field is what the Goal System uses to inject continuation directives.** It appears in the chat as a system-level message that Copilot processes as if the system said it. This is **not** a user message — it's a hidden system instruction that shapes the next LLM call.

## 1. How the Terminal Wake Works (And Why It's Hard to Replicate)

The background terminal notification is **internal to VS Code's Copilot Chat extension**. It's not exposed via any public API. When an async terminal finishes, the Copilot Chat extension detects the process exit internally and re-activates the chat session through its own event bus.

**Evidence:** I searched the entire Goal System codebase and found **zero** references to any terminal-wake API. If such an API existed, the Goal System author would have used it instead of the hook-interception pattern.

You cannot replicate this exact mechanism from outside VS Code because:

- VS Code doesn't expose "fire a terminal completion event" to external processes
- The internal event bus between the integrated terminal and Copilot Chat is private
- There's no `workbench.action.chat.wakeFromTerminal` command
