## Architecture Overview

```
registry/{id}.js  ──┐
                     ├──► registry/index.js (static import array)
REGISTRY_TEMPLATE.js ┘         │

                      providers/index.js

     PROVIDERS[id]    PROVIDER_MODELS[alias]    PROVIDER_OAUTH[id]  PROVIDER_MEDIA[id]
     (transport)      (normalized model[])      (oauth flow)        (media services)
```

**Data flow:**
1. Each `registry/{id}.js` exports a single default `RegistryEntry` object
2. `registry/index.js` (auto-generated by `scripts/migrate-registry.mjs` / `injectDisplayToRegistry.mjs`) static-imports all entries into an array
3. `providers/index.js` iterates the array once and populates four top-level maps:
   - `PROVIDERS[id]` — built from `entry.transport` via `buildTransport()`
   - `PROVIDER_MODELS[alias]` — `entry.models.map(normalizeModel)`
   - `PROVIDER_OAUTH[id]` — `entry.oauth`
   - `PROVIDER_MEDIA[id]` — aggregated from media-key fields + legacy `entry.media`

**Key invariant:** Transport and models are *co-located* in one file per provider. No separate "model catalog" file — every model lives in the same registry file as its provider.

## Infrastructure Files

### providers/index.js

**Single source of truth** for building the four runtime maps from the registry array.

#### Exports
| Export | Type | Description |
|--------|------|-------------|
| `PROVIDERS` | `Record<id, TransportConfig>` | Built from `entry.transport` for each entry with a transport |
| `PROVIDER_MODELS` | `Record<alias, NormalizedModel[]>` | Normalized model list (alias defaults to id) |
| `PROVIDER_OAUTH` | `Record<id, OAuthConfig>` | Entries with an `oauth` block |
| `PROVIDER_MEDIA` | `Record<id, MediaConfig>` | Aggregated media/service fields |

#### Core functions

```js
buildTransport(transport, oauth)
```
- Shallow-clones transport, fills `format: "openai"` default when absent
- Injects `clientId`, `clientSecret`, `tokenUrl` from `oauth` block into transport (so executors reading `config.{clientId,tokenUrl}` don't need to duplicate them in both places)

#### The loop

```js
for (const entry of REGISTRY) {
  if (entry.transport) {
    PROVIDERS[entry.id] = buildTransport(entry.transport, entry.oauth);
    if (entry.transports) PROVIDERS[entry.id].transports = entry.transports; // multi-endpoint
  }
  if (entry.models !== undefined) PROVIDER_MODELS[entry.alias || entry.id] = entry.models.map(normalizeModel);
  if (entry.oauth) PROVIDER_OAUTH[entry.id] = entry.oauth;
  // MEDIA_KEYS aggregation...
}
Object.assign(PROVIDER_MODELS, buildTtsProviderModels()); // TTS voice tables
```

**MEDIA_KEYS set:** `serviceKinds, ttsConfig, sttConfig, embeddingConfig, imageConfig, imageToTextConfig, videoConfig, musicConfig, searchViaChat, searchConfig, fetchConfig, modelsFetcher, mediaPriority, hiddenKinds`

## Architecture Overview

The translator is the **provider-agnostic routing/translation engine** that pivots requests and responses between wire formats. The design principle:

> **OpenAI chat completions is the hub format.** Every non-OpenAI provider has a translator pair `X:openai` (inbound) and `openai:X` (outbound). Most translations route `source → openai → target` through a double-hop. **Direct routes** (e.g. `claude:kiro`, `kiro:claude`) bypass the hub when the double-hop would lose fidelity (thinking blocks, tool ids, non-base64 images, `is_error` flags).

```

│ Claude SSE   │           │ Kiro AWS ES  │
│ (Messages)   │─────┬────▶│ CodeWhisperer│

                     │ direct claude:kiro

│ OpenAI Chat  │◀────┴────▶│ Gemini       │
│ (hub format) │           │ (contents[]) │

        │ hub                     │ hub

│ Ollama       │           │ Antigravity  │
│ Cursor       │           │ Gemini CLI   │
│ CommandCode  │           │ Vertex AI    │
│ Responses    │           │              │

```

### Request Lifecycle
1. `src/app/api/v1/*` route parses inbound request
2. `src/sse/handlers/chat.js` picks provider via combo/account fallback
3. `open-sse/handlers/chatCore.js` calls `translateRequest(sourceFormat, targetFormat, ...)`
4. Translator picks `source:target` direct route OR pivots through OpenAI
5. Post-translation hooks: `applyThinking`, `filterToOpenAIFormat`, `prepareClaudeRequest`, `cloakClaudeTools`
6. Executor dispatches upstream
7. Streaming chunks flow back through `translateResponse(targetFormat, sourceFormat, ...)`

### Design Principles
- **Self-registration** via ES module side-effect imports (`import "./request/X.js"` at bottom of `index.js`)
- **Config-driven** — capabilities, thinking ranges, model quirks come from `providers/capabilities.js` + `config/providerModels.js`, never hardcoded per-model in translators
- **Fail-soft** — RTK pre-translate hooks, unknown tool types, malformed JSON all fall through cleanly
- **Lossless for fragile pairs** — direct routes exist when the OpenAI hub would drop information

### `translateRequest(sourceFormat, targetFormat, model, body, stream, credentials, provider, reqLogger, stripList, connectionId, clientTool)`

Pipeline:
1. **`stripContentTypes`** — opt-in via `strip[]` in PROVIDER_MODELS (image/audio blocks)
2. **`normalizeThinkingConfig`** — remove thinking if lastMessage isn't user
3. **`ensureToolCallIds`** — fix missing/malformed tool IDs
4. **`fixMissingToolResponses`** — insert empty tool responses (skipped for Kiro; Kiro has stricter source-aware reconciliation)
5. **`captureThinking`** — snapshot thinking intent BEFORE format translation
6. **`captureSessionId`** — snapshot session ID from envelope (e.g. antigravity `request.sessionId`)
7. **Translation dispatch:**
   - Same format → skip
   - Direct route exists → use it (`claude:kiro`, `kiro:claude`, `openai:openai-responses`)
   - Otherwise: `source → openai → target` double-hop, with `reqLogger.logOpenAIRequest()` on the intermediate
8. **`applyThinking`** — re-apply in provider-native format (unless Kiro translator already mapped it)
9. **`filterToOpenAIFormat`** — normalize to clean OpenAI shape when target is OpenAI
10. **`prepareClaudeRequest`** — final Claude-specific prep (cache_control, tool_use ordering, cloaking)
11. **`cloakClaudeTools`** — rename client tools with `_cc` suffix for OAuth (anti-ban)

### `translateResponse(targetFormat, sourceFormat, chunk, state)`

Pipeline:
1. Same format → return chunk as-is
2. Direct route (`kiro:claude`, `openai:openai-responses`) → use it
3. Otherwise: `target → openai → source` double-hop
4. Attaches `_openaiIntermediate` for logging when both sides are non-OpenAI

|---|---|

  ├─ Within refresh lead window? → YES
  └─ Stale for trackRefreshAt provider? → YES

oauthCredentialManager.refreshProviderCredentials(provider, credentials)

  ├─ Existing lock? → await same promise
  └─ No lock → proceed

dedupRefresh(provider, oldToken, fn, log)
  ├─ In-flight? → reuse promise
  ├─ Recent result (<10s)? → reuse result
  └─ Execute → cache result

HTTP POST to provider token endpoint

mergeRefreshedCredentials(provider, current, refreshed)

Return merged credentials → persist via onCredentialsRefreshed callback
```

## Account Fallback Algorithm

```
Request to combo model → handleComboChat()

For each model in rotatedModels:
  1. Try handleSingleModel(body, modelStr)
  2. Success (2xx) → return response + append x-9r-fallback-chain header
  3. Failure → checkFallbackError(status, errorText, backoffLevel)
     ├─ Match ERROR_RULES text rule → cooldown from rule or exponential backoff
     ├─ Match ERROR_RULES status rule → same
     └─ No match → TRANSIENT_COOLDOWN_MS
  4. shouldFallback=false → return error response immediately
  5. shouldFallback=true → record error, try next model
     └─ Transient 502/503/504 with short cooldown → wait before next attempt

All models failed → 503 with earliest retryAfter + fallbackChain in body
```

**Model Lock System:** Per-connection flat fields (`modelLock_${model}`) prevent retrying a model that recently failed for a specific model ID. Cleared on success via `buildClearModelLocksUpdate`.

## Driver Chain & Fallback Order

The driver chain lives in `src/lib/db/driver.js`. It uses a singleton pattern stored on `global._dbAdapter` to survive Next.js hot-reload cycles.

### Selection Order by Runtime

```

│  Bun Runtime                                            │

│  │ bun:sqlite   │───▶│   sql.js     │                   │
│  │ (built-in)   │ ✗  │ (pure JS)    │                   │

│  Node.js Runtime                                        │

│  │better-sqlite3│─▶│ node:sqlite  │─▶│   sql.js     │   │
│  │  (optional   │
│  │     │✗ │  (≥22.5)     │✗ │ (pure JS)    │   │

```

### Adapter Common Interface

All adapters return an object with this shape:

```js
{
  driver: string,           // "bun:sqlite" | "better-sqlite3" | "node:sqlite" | "sql.js"
  run(sql, params),         // → { changes, lastInsertRowid }
  get(sql, params),         // → single row or undefined
  all(sql, params),         // → array of rows
  exec(sql),                // multi-statement exec
  transaction(fn),          // wraps fn() in a transaction/savepoint
  checkpoint(),             // PRAGMA wal_checkpoint(TRUNCATE)
  close(),                  // graceful shutdown
  raw,                      // underlying DB instance
}
```

### Key Adapter Differences

| Feature | bun:sqlite | better-sqlite3 | node:sqlite | sql.js |
|---------|-----------|---------------|-------------|--------|
| **Statement cache** | ✅ Map | ✅ Map | ✅ Map | ❌ (prepare per call) |
| **WAL checkpoint** | 60s interval | 60s interval | 60s interval | N/A (in-memory) |
| **Transaction** | `db.transaction(fn)()` | `db.transaction(fn)()` | SAVEPOINT wrapper | SAVEPOINT wrapper |
| **Persistence** | Native file I/O | Native file I/O | Native file I/O | Debounced `writeFileSync` (100ms) |
| **Shutdown hooks** | beforeExit/SIGINT/SIGTERM | beforeExit/SIGINT/SIGTERM | beforeExit/SIGINT/SIGTERM | beforeExit/SIGINT/SIGTERM |
| **Install required** | No (Bun built-in) | Optional native dep | No (Node ≥22.5) | npm package (WASM) |

### Singleton & Hot-Reload Safety

```js
// global._dbAdapter survives Next.js dev hot-reload
if (!global._dbAdapter) global._dbAdapter = { instance: null, initPromise: null, logged: false };
```

- `getAdapter()` — async, returns cached adapter or initializes once
- `getAdapterSync()` — throws if not yet initialized; for use after first await

## 2. Provider contract (the shape every provider must implement)

Every file under `providers/*.js` exports a default object with these fields:

| Field | Required | Notes |
|---|---|---|
| `config` | ✓ | Imported from `constants/oauth.js`. Holds `clientId`, `authorizeUrl`, `tokenUrl`, scopes, `codeChallengeMethod`, etc. |
| `flowType` | ✓ | One of `authorization_code_pkce`, `authorization_code`, `device_code`, `import_token`. |
| `buildAuthUrl(config, redirectUri, state, codeChallenge, meta)` | PKCE/code flows | Returns the browser URL. |
| `exchangeToken(config, code, redirectUri, codeVerifier, state, meta)` | PKCE/code flows | POSTs to token endpoint, returns raw JSON. |
| `requestDeviceCode(config, codeChallenge, options)` | device_code only | Returns `{device_code, user_code, verification_uri_complete, interval, _clientId, _clientSecret, …}`. |
| `pollToken(config, deviceCode, codeVerifier, extraData)` | device_code only | Returns `{ok, data}`; `data.error = 'authorization_pending'` keeps polling. |
| `mapTokens(rawTokens, extra)` | ✓ | Normalizes into `{accessToken, refreshToken, idToken, expiresIn, email, providerSpecificData}`. |
| `prepareConfig(config, meta)` | optional | Async — lets providers customize config per-session (GitLab user-supplied `clientId`/`baseUrl`, Trae's `loginTraceID`, Zed's RSA key). |
| `postExchange(tokens)` | optional | Async — extra HTTP calls after token exchange (Antigravity onboarding, Codex profile, Kiro ARN lookup). |
| `fixedPort`, `callbackPath` | optional | Override local callback server port/path. |

The `PROVIDERS` map in `providers/index.js` keys by provider id. `getProvider()` normalizes legacy aliases (`kimi-coding` → `kimi`).

- **Zed** passes an encoded RSA private key as `codeVerifier` instead of a PKCE verifier.

## 4. Flow types in practice

### 4a. `authorization_code_pkce` (Claude, Codex, xAI, Grok CLI, Gemini CLI, Kimi, Kilocode, Cline, Clinepass, Trae, Windsurf, Zed, Codebuddy-*, Kimchi, GitHub, GitLab, iFlow, Qoder)
Standard RFC 7636. Local HTTP server on 127.0.0.1 listens on `/callback`, browser redirects there with `?code=&state=`, we exchange with the PKCE verifier. `generatePKCE(bytes)` defaults to 32 random bytes (xAI uses 96).

### 4b. `authorization_code` (Antigravity — Google-flavored)
Same shape but uses a `client_secret` instead of PKCE. `access_type=offline` + `prompt=consent` forces refresh token issuance.

### 4c. `device_code` (Kiro)
AWS SSO OIDC. Three HTTP calls:
1. `POST https://oidc.{region}.amazonaws.com/client/register` — dynamic client registration, returns ephemeral `clientId`/`clientSecret`.
2. `POST …/device_authorization` — returns `deviceCode`, `userCode`, `verificationUriComplete`.
3. `pollToken` polls `…/token` with grant `urn:ietf:params:oauth:grant-type:device_code` until `accessToken` arrives or `authorization_pending`.

The ephemeral client credentials are persisted into `providerSpecificData` so refresh works later. Region is user-selectable (`us-east-1` default) and validated by `assertValidAwsRegion`. Auth method is either `builder-id` (default) or `idc`.

### 4d. `import_token` (Cursor)
No OAuth flow at all. The Cursor IDE stores its bearer token in a local SQLite database; 9Router has a `/api/oauth/cursor/import` route that reads it. `mapTokens` just normalizes the already-extracted token and tags it with `machineId` + `authMethod: "imported"`.

## 5. Provider-specific quirks

### `claude.js`
- `buildAuthUrl` adds `code=true` (Claude-specific query param).
- `exchangeToken` handles `code` values that carry a trailing `#substate` fragment — splits on `#` and forwards both parts in the JSON body.
- Content-Type `application/json` (unlike most peers which use form-encoded).

### `codex.js` (OpenAI ChatGPT)
- Fixed callback port **1455** (`CODEX_CONFIG.fixedPort`) because OpenAI's allowlist is static.
- Extracts email + `chatgptAccountId` + `chatgptPlanType` from the `id_token` JWT's `https://api.openai.com/auth` claim (via `extractCodexAccountInfo`), falling back to the `email` claim in the access token JWT.
- `providerSpecificData.chatgptAccountId` is critical — it's the ChatGPT org/account the token is scoped to, used for model routing.

### `kiro.js` (AWS Builder ID / IAM Identity Center)
- Device code flow (see §4c).
- After successful poll, if `profileArn` is missing (common with Builder-ID tokens), the orchestrator calls `fetchKiroProfileArn(accessToken)` which POSTs to `https://codewhisperer.us-east-1.amazonaws.com/ListAvailableProfiles` and grabs the first ARN. Without this, downstream Kiro calls return 403.
- Stores `_clientId`, `_clientSecret`, `_region`, `_authMethod`, `_startUrl` inside the persisted `providerSpecificData` so refresh can re-sign.

### `cursor.js`
- Pure import flow — `mapTokens` is the only meaningful method. `refreshToken: null` (Cursor has no public refresh endpoint; when the imported token expires, user must re-import).

### `antigravity.js` (Google Code Assist / Gemini-for-IDE)
- Plain `authorization_code` with client secret.
- `postExchange` does three extra calls:
  1. `GET userInfoUrl?alt=json` — email.
  2. `POST loadCodeAssistEndpoint` with `{metadata}` — returns `cloudaicompanionProject.id` and the default `allowedTiers[].id`.
  3. **Fire-and-forget onboarding loop**: up to 10 attempts, 5 s apart, POSTs to `onboardUserEndpoint` with `{tierId, metadata}` until `done === true`. Does not block the DB save.
- `mapTokens` flattens `projectId` to the top level so the upstream executor can attach it to Gemini requests.

## 7. `utils/server.js` — callback server + Codex proxy

**`startLocalServer(onCallback, fixedPort)`** — generic HTTP server on `127.0.0.1`. Serves `/callback` and `/auth/callback`, returns a success HTML page with a 3 s auto-`window.close()` countdown. **`startCodexProxy(appPort)`** — singleton fixed-port (1455) server with two modes:
- **Mode A (server-side exchange)**: if `registerCodexSession({state, codeVerifier, redirectUri})` was called before the popup opened, the proxy itself exchanges the code, writes the row via `createProviderConnection`, sets `session.status = "done"`, and renders a success page. - **Mode B (legacy channel fallback)**: no registered session → 302 redirect to the dashboard's `/callback` on `appPort` so the old `BroadcastChannel`-based flow handles it.

## 11. Data flow through the gateway (putting it together)

1. Dashboard calls `GET /api/oauth/{provider}/start` → `generateAuthData(provider, redirectUri, meta)` → returns `authUrl` + `state`.
2. Browser navigates user to provider's authorize URL.
3. Provider redirects to `http://localhost:{port}/callback?code=&state=`.
   - Codex hits port 1455 proxy first (Mode A auto-exchanges and writes DB; Mode B redirects to dashboard).
4. Dashboard receives callback, calls `exchangeTokens(provider, code, redirectUri, codeVerifier, state, meta)`.
5. `provider.exchangeToken` → `provider.postExchange` (Antigravity onboarding, Codex/Kiro profile fetch) → `provider.mapTokens`.
6. Result persisted via `createProviderConnection({provider, authType:"oauth", ...tokenData})` into SQLite (`src/lib/db/repos/providerConnections`).
7. On each chat request, `open-sse/handlers/chatCore.js` picks a connection for the selected provider, refreshes the access token if `expiresAt` is near, and uses the resulting bearer for the upstream call.

---

## 12. Key architectural patterns worth preserving

- **Provider plugin model**: add a new provider by dropping one file in `providers/`, importing it in `providers/index.js`, and adding its constants to `constants/oauth.js`. No other file changes needed.
- **PKCE as default, opt-out for legacy**: only Antigravity uses `authorization_code` without PKCE (because Google still requires `client_secret` for that client type).
- **Post-exchange hook** cleanly separates "get tokens" from "get the rest of the user's profile/project data", keeping `exchangeToken` focused.
- **Fixed-port proxy pattern** (Codex, xAI) solves providers with a static redirect-URI allowlist, while keeping a legacy fallback path for older dashboard clients.
- **JWT introspection over extra HTTP**: email/account-id pulled from the `id_token` or access-token JWT whenever the claim exists; network calls only when necessary (Kiro ARN, Antigravity user info).
- **Origin-guarded callback server** blocks login-CSRF on the loopback redirect without needing a nonce cookie.
- **`_`-prefixed fields** (`_clientId`, `_clientSecret`, `_region`) on device-code poll results carry ephemeral registration data through to `mapTokens` and into DB persistence so refresh doesn't need to re-register.
- **Run-once backfill guards** (`codexBackfillDone` flag) for schema migrations that need to patch existing rows exactly once per process.

# 9Router MITM System Deep Dive

## Architecture Overview

The MITM (Man-in-the-Middle) system is a **local HTTPS proxy** that intercepts AI IDE traffic to redirect requests through 9Router's multi-provider gateway. It operates via three pillars:

1. **DNS hijacking** — rewrites `/etc/hosts` to route IDE traffic to `127.0.0.1:443`
2. **Dynamic TLS certificate generation** — issues per-domain leaf certs signed by a local Root CA trusted by the OS
3. **Per-IDE handlers** — translate native IDE request formats (Gemini, CodeWhisperer, protobuf, OpenAI) into 9Router's OpenAI-compatible API

```
IDE Tool (Cursor/Kiro/Copilot/AG)
  │ DNS: api2.cursor.sh → 127.0.0.1

MITM Server (:443)
  │ SNI → generate leaf cert for domain
  │ TLS handshake (trusted by OS Root CA)

Request Handler
  │ Match URL_PATTERNS[tool]
  │ Extract model → MODEL_SYNONYMS/PATTERNS → mappedModel
  │ Handler: translate body → OpenAI format

9Router Gateway (:20128/v1/*)
  │ Multi-provider routing + fallback

Upstream Provider (Claude/GPT/Gemini/etc.)
```

### 1. `src/mitm/server.js` — Main MITM Proxy Server

**Purpose:** The HTTPS server that listens on port 443, handles TLS via SNI, intercepts requests, and forwards to 9Router or upstream.

**Key exports:** None (standalone executable — `server.listen()`)

**Core flow:**
- **SNI callback** (`sniCallback`): On each TLS connection, generates/caches a leaf cert for the requested domain via `getCertForDomain()`. Certs include the full chain (`leafCert + rootCAPem`).
- **Port 443 binding**: Kills any existing process on port 443 via `killPort()` using `lsof` (macOS/Linux) or PowerShell `Get-NetTCPConnection` (Windows).
- **Request dispatch**:
  1. `/_mitm_health` → health check endpoint
  2. Anti-loop: skip if `x-request-source: local` header present (prevents 9Router→MITM loops)
  3. Match host → `getToolForHost()` → tool name (`antigravity`, `copilot`, `kiro`, `cursor`)

**Upstream forwarding** (`passthrough`):
- ALPN negotiation cache (`h2` vs `http/1.1`)
- HTTP/2 path: uses `node:http2` with custom TLS connection to resolved IP (bypasses DNS loop)
- HTTP/1.1 fallback: `https.request` to resolved IP with `servername` for SNI

## 1. Auth Model (`src/dashboardGuard.js`)

There is **no `src/middleware.js`**. Auth is enforced by `dashboardGuard.js`, wired through the custom server layer. Three tiers:

| Tier | Paths | Auth |
|------|-------|------|
| **Public** | `/api/health`, `/api/init`, `/api/locale`, `/api/auth/*`, `/api/version`, `/api/settings/require-login` | None |
| **API-key gated** | `/v1/*`, `/v1beta/*`, `/api/v1/*`, `/api/v1beta/*`, `/codex/*` | Bearer API key validated *inside* each handler via `validateApiKey()` |
| **Dashboard JWT** | `/api/settings`, `/api/keys`, `/api/providers`, `/api/combos`, `/api/models`, `/api/usage`, `/api/oauth`, `/api/tunnel`, `/api/cli-tools`, `/api/mcp`, `/api/translator`, `/api/proxy-pools`, etc. | `auth_token` cookie (JWT) or `x-9r-cli-token` header (machine-ID derived) |

**Special rules:**
- `ALWAYS_PROTECTED` (`/api/shutdown`, `/api/settings/database`, `/api/version/update`, auto-import routes): JWT required even if `requireLogin=false`.
- `LOCAL_ONLY_PATHS` (cli-tools, tunnel, headroom, mcp, auto-import, reset-password): restricted to loopback IPs via `x-9r-real-ip` from `custom-server.js`.
- Tunnel/Tailscale requests blocked from dashboard if `tunnelDashboardAccess !== true`.

**Dashboard auth flow:** `POST /api/auth/login` → bcrypt compare against stored hash (or `INITIAL_PASSWORD` env, default `123456`) → sets `auth_token` JWT cookie. Supports OIDC alternative (`authMode: "oidc"`). Login rate-limiter with IP-based lockout.
